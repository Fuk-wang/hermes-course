给 Hermes 接上模型

Providers / Model Configuration

模型写在哪、密钥放哪、怎么验证

Hermes 装好了却还没连上任何模型，敲什么都得不到回复。这一节把 provider（提供商）、模型 ID 和 API Key 三样东西摆到正确的位置，直到你能在会话里换着模型用。

01这一步在解决什么#

Hermes 本身不带模型。它只是一个 agent 外壳：真正思考、写代码、决定调哪个工具的，是你在配置里指定的那个大语言模型。所以「至少配置一个提供商」是使用 Hermes 的前置条件，没配好之前安装再顺利也聊不起来。

官方把这件事拆得很干净：能公开写的东西（用哪家、哪个模型、哪个端点）写进 ~/.hermes/config.yaml；不能公开的东西（API 密钥、token）写进 ~/.hermes/.env。搞混这两个文件是最常见的新手事故——把密钥塞进 config.yaml 会在分享配置时泄漏，把模型名塞进 .env 则会完全不生效。

配好之后换模型是随时的事，没有锁定：官方明确说明可以随时用 hermes model 切换提供商，你的对话历史、记忆和技能都会保留。所以这一节的目标不是「一次选对」，而是搞清楚配置怎么读、怎么写、怎么验证。

021. 先认清两个文件：config.yaml 管模型，.env 管密钥#

Hermes 把配置和机密分开存放。非密钥配置（模型、终端后端、压缩设置、内存限制、工具集等）写在 ~/.hermes/config.yaml；密钥和 token（API 密钥、bot token、密码）写在 ~/.hermes/.env。官方给的经验法则很直接：机密放 .env，其他所有内容放 config.yaml，两者都设置同一项时 config.yaml 对非机密设置优先。

还有第三个文件要注意：~/.hermes/auth.json 存放 OAuth 提供商凭据（例如 Nous Portal）。走浏览器登录那类提供商时，key 不会出现在 .env 里，凭据由 Hermes 自己存进 auth.json，并且可以自动刷新。

配置的解析顺序（优先级从高到低）是：CLI 参数（如 hermes chat --model ...，仅本次调用生效）、~/.hermes/config.yaml、~/.hermes/.env、内置默认值。这也是为什么临时试验某个模型不用改任何文件——加个命令行参数就行。

  • .env —— API 密钥、bot token、密码。别提交到 git，也别贴到聊天里。
  • auth.json —— 浏览器 OAuth 登录（Nous Portal、Codex、Copilot、xAI Grok OAuth 等）得到的凭据。

032. provider 与 model 到底怎么填#

config.yaml 的 model: 节通常只要三样东西：provider（谁来提供服务）、default（模型 ID）、必要时 base_url（自定义或兼容端点）。model key 还有个别名：在 model: 配置节中，可以用 default: 或 model: 作为模型 ID 的键名，model: { default: my-model } 和 model: { model: my-model } 效果完全相同。

provider 的取值有三种形态。第一种是内置 provider 名，例如 openrouter、anthropic、gemini、deepseek、minimax、zai（z.ai / GLM）、kimi-coding、alibaba（Qwen Cloud / DashScope）；这些是「一等提供商」，有专属 provider ID，很多还支持短别名（例如 --provider claude 和 --provider claude-code 是 --provider anthropic 的简写）。

第二种是裸的 custom，配合 base_url 指向任意 OpenAI 兼容端点。第三种是 custom:<名字>，指向你在 custom_providers: 里命名过的端点——配好名字后就能用 /model custom:local:qwen-2.5 这样的三段式语法（custom:名字:模型）在会话中途切换。

yaml一个内置提供商 + 一个命名的自定义端点
model:
  provider: "gmi"
  default: "zai-org/GLM-5.1-FP8"

custom_providers:
  - name: local
    base_url: http://localhost:8080/v1
    # api_key 省略 —— Hermes 对无 key 的本地服务器使用 "no-key-required"
  - name: work
    base_url: https://gpu-server.internal.corp/v1
    key_env: CORP_API_KEY
    api_mode: chat_completions
provider 写法什么时候用文档中的例子
内置名：openrouter想省事、一家聚合器打通所有模型model: { provider: openrouter, default: anthropic/claude-opus-4.7 }
内置名：gemini / minimax / zai / deepseek直连某一家，用它的专属端点和密钥hermes chat --provider zai --model glm-5
custom本地模型或任意 OpenAI 兼容 APImodel: { provider: custom, base_url: http://localhost:11434/v1 }
custom:<名字>你有多个自定义端点，想按名字区分/model custom:local:qwen-2.5
辅助模型默认跟着主模型走

即使使用 Nous Portal、Codex 或自定义端点，某些工具（视觉、网页摘要、MoA）仍会使用单独的「辅助」模型。默认情况下（auxiliary.*.provider: "auto"），Hermes 将这些任务路由到你在 hermes model 中选择的同一模型；想省钱可以按任务覆盖到更便宜/更快的模型。

043. API Key 从哪来：控制台申请，写进 .env，变量名必须对#

密钥的来源永远在提供商那边：去它自己的控制台或订阅页申请，Hermes 只是读取。拿到之后把 KEY=value 一行写进 ~/.hermes/.env，或者用 hermes config set <变量名> <值>（自动落到 .env）。也可以用 export <变量名>=... 临时覆盖。

关键是变量名不能写错。Hermes 只认固定的环境变量名，写成别的拼法就等于没配。常见的有：OPENROUTER_API_KEY、GOOGLE_API_KEY（Gemini，别名 GEMINI_API_KEY）、ANTHROPIC_API_KEY、DEEPSEEK_API_KEY、DASHSCOPE_API_KEY、GLM_API_KEY、KIMI_API_KEY / KIMI_CN_API_KEY、MINIMAX_API_KEY / MINIMAX_CN_API_KEY、XAI_API_KEY、HF_TOKEN。

部分基础 URL 也能用环境变量覆盖，例如 NOVITA_BASE_URL、GLM_BASE_URL、KIMI_BASE_URL、MINIMAX_BASE_URL、DASHSCOPE_BASE_URL、XIAOMI_BASE_URL、GMI_BASE_URL、TOKENHUB_BASE_URL。不过多数情况不用手写——比如使用 Z.AI / GLM 提供商时，Hermes 会自动探测多个端点（全球版、中国版、编程版）以找到接受你 API key 的那个，可用端点会被自动检测并缓存。

bash三种写法，效果一样（都进 .env）
# 1) 直接写文件
echo "GOOGLE_API_KEY=..." >> ~/.hermes/.env

# 2) 让 Hermes 帮你写
hermes config set OPENROUTER_API_KEY sk-or-...

# 3) 只在当前终端生效
export ANTHROPIC_API_KEY=...
hermes chat --provider anthropic --model claude-sonnet-4-6

054. 抄三段配置：OpenRouter、Google Gemini、国产直连#

OpenRouter 是最省事的起点，一家聚合器能路由到 Claude、GPT、Gemini、DeepSeek 等各家模型，官方也把「只想让它工作」这一档归给 OpenRouter 或 Nous Portal。它的密钥变量是 OPENROUTER_API_KEY。

Google Gemini 走原生适配器：基础 URL 用 https://generativelanguage.googleapis.com/v1beta，Hermes 检测到该端点后会创建原生 Gemini 适配器，内部把请求转换为 Gemini 原生 schema。官方明确建议 Hermes 会话优先使用这个原生端点，而不是它的 OpenAI 兼容端点。

国产模型大多是「一等提供商」，有专属 provider ID 和密钥变量，配置方式和内置提供商完全一致。MiniMax 用 minimax + MINIMAX_API_KEY（中国端点用 minimax-cn + MINIMAX_CN_API_KEY），z.ai / GLM 用 zai + GLM_API_KEY，Kimi 中国版用 kimi-coding-cn + KIMI_CN_API_KEY。

065. 本地模型与自托管端点：provider: custom#

Hermes 可与任何 OpenAI 兼容 API 端点配合使用：只要服务器实现了 /v1/chat/completions，就可以把 Hermes 指向它。这意味着本地模型、GPU 推理服务器、多提供商路由器或任何第三方 API 都能接。

Ollama 是最常见的入门选择：它默认在 11434 端口提供 OpenAI 兼容 API，不需要 API key，配置时把 base_url 写成 http://localhost:11434/v1 即可，跳过密钥。要注意 Ollama 默认不使用模型的完整上下文窗口，小于 24 GB 显存时只有 4,096 token，官方建议带工具的 agent 使用至少 16k–32k 上下文。

如果手上有多个端点（本地开发服务器 + 远程 GPU 服务器），在 custom_providers: 下给它们起名字，用 key_env 指定密钥变量、用 api_mode 指定传输方式（chat_completions 或 anthropic_messages）。某些 OpenAI 兼容端点需要特定于提供商的请求体字段，可以用 extra_body 映射，Hermes 会把它合并到该端点的每个请求中。

076. hermes model 与 /model：一个负责配置，一个负责切换#

Hermes 有两个模型命令，用途完全不同。hermes model 在终端里运行（任何聊天会话之外），是完整的配置向导——添加提供商、运行 OAuth、输入 API key、配置端点；选择结果写入 ~/.hermes/config.yaml 的 model.provider 和 model.model 字段。

/model 在活跃的 Hermes 聊天会话中输入，只能在已配置的提供商和模型之间快速切换。它无法添加新提供商、运行 OAuth 或提示输入 API key——如果你只配置了一个提供商（如 OpenRouter），/model 只会显示该提供商的模型。

要添加新提供商，正确顺序是：退出会话（Ctrl+C 或 /quit），运行 hermes model，完成提供商配置，然后开启新会话。切换提供商时，Hermes 会将基础 URL 和提供商持久化到配置中，使更改在重启后保留；从自定义端点切换到内置提供商时，过时的基础 URL 会自动清除。

bash配置：在终端里跑向导
hermes model
# → 选择提供商（如 "Anthropic"、"Nous Portal"、"Custom endpoint"）
# → 完成 OAuth 或粘贴 API key
# → 从该提供商的精选模型列表中选择
bash切换：在会话里热切（不重启、不丢对话）
/model openrouter:claude-sonnet-4
/model custom:together:meta-llama/Llama-3.3-70B-Instruct-Turbo
/model custom:together:google/gemma-4-31b-it
bash顺带：持久化到 config.yaml 的斜杠命令写法
/model gpt-5.4 --provider openrouter              # 仅当前会话
/model gpt-5.4 --provider openrouter --global     # 同时持久化到 config.yaml
命令运行位置功能
hermes model终端（任何会话之外）完整配置向导 —— 添加提供商、运行 OAuth、输入 API key、配置端点
/modelHermes 聊天会话内部在已配置的提供商和模型之间快速切换
/model custom 会自动探测端点

/model custom（不带模型名称）会查询端点的 /models API，如果只加载了一个模型则自动选择 —— 适用于运行单个模型的本地服务器。

087. 怎么确认换模型真的生效#

最直观的验证是开一个新会话：欢迎横幅会显示你选择的模型/provider，以及可用工具和 skills。如果能无错误地回复、必要时还能调用工具（终端、文件读取、网页搜索），并且对话能正常进行超过一轮，就说明接上了。

命令行侧有两个直接读配置的命令：hermes config get model 查看 CLI 当前实际使用的模型配置，hermes status 看整体状态。hermes doctor 会检查配置问题，也应该被用来确认没有残留的配置警告。

还有一个信号值得记住：启动时会出现 Context limit: X tokens 这样一行，它显示 Hermes 认为的上下文大小。如果你配的是本地模型而这里数字很小，说明模型的上下文窗口没配好，而不是模型「变笨」了。

bash改完配置后的一轮自检
hermes config get model      # CLI 当前实际使用的配置
hermes status                # 整体状态
hermes doctor                # 配置体检
hermes                       # 开新会话，看横幅显示的模型
  • CLI（hermes chat）：下次执行 hermes chat 时生效。
  • Gateway（Telegram、Discord、Slack 等）：下一个新会话生效；现有会话保持原有模型，要强制全部生效需 hermes gateway restart。
  • 仪表板聊天标签页（/chat）：下一个新 PTY 生效；当前打开的聊天保持原有模型，在聊天内用 /model 热切换。
  • 想配一个「主模型挂了自动顶上」的备用链，用 config.yaml 顶层的 fallback_providers:（或 hermes fallback）——故障转移仅通过 config.yaml 配置。

为什么当前会话没变

更改不会使运行中会话的 prompt 缓存失效。这是有意为之：在会话内切换主模型需要重置缓存（系统 prompt 包含模型特定内容），该操作保留给聊天内的显式 /model 斜杠命令。

常见坑

01在会话里敲 /model，找不到我还没配过的供应商。+

/model 只能在已配置的提供商和模型之间切换，它无法添加新提供商、运行 OAuth 或提示输入 API key。只配置了 OpenRouter 时，/model 就只会显示 OpenRouter 的模型。正确做法：退出会话（Ctrl+C 或 /quit），运行 hermes model 完成提供商配置，然后开启新会话。

02我把模型写进了 .env（OPENAI_BASE_URL / LLM_MODEL），为什么不生效？+

这两个旧版环境变量已移除，Hermes 的任何部分都不再读取它们 —— config.yaml 是模型和端点配置的唯一来源；过时条目会在下次 hermes setup 或配置迁移时自动清除。请改用 hermes model 或直接编辑 config.yaml 的 model: 节。反过来，把 API 密钥写进 config.yaml 也不对，密钥属于 .env。

03本地模型聊两句就像忘了前面的话，或者启动时直接被拒。+

多半是上下文窗口。Hermes 要求模型至少具备 64,000 token 的上下文窗口，不够的模型启动时会被拒绝。Ollama 另有坑：它默认不使用完整上下文（小于 24 GB 显存只有 4,096 token），而无法通过 OpenAI 兼容 API 设置上下文长度，必须在服务端配置或写进 Modelfile —— 用 OLLAMA_CONTEXT_LENGTH=32768 ollama serve，再用 ollama ps 看 CONTEXT 列确认。也可以直接在 config.yaml 里显式写 context_length。

04在配置文件或仪表板里换了主模型，正在聊的会话怎么没变？+

符合预期。配置写入 config.yaml，只有新会话会读取：CLI 下次 hermes chat 生效，Gateway 从下一个新会话生效，仪表板聊天标签页下一个新 PTY 生效。当前打开的聊天是一个活跃的 agent 进程，它保持启动时的模型——要在该会话内立刻换，就用 /model <name> 热切换；要让 Gateway 上的所有会话统一生效，重启它（hermes gateway restart）。

05我明明选了某家的模型，Hermes 却把请求发给了另一家。+

在 OpenRouter（或任何聚合器）上，裸模型名称会优先在聚合器内解析：OpenRouter 上的 claude-sonnet-4 会解析为 anthropic/claude-sonnet-4.6，仍然走你的 OpenRouter 认证；只有在原生 Anthropic 认证下，claude-sonnet-4 才会保持为 claude-sonnet-4-6。出现意外的提供商切换时，先确认当前 provider 是否符合预期——选择器始终在对话框顶部显示当前主模型。
