把命令行用起来

CLI

在终端里把 Hermes 用顺手

你已经装好 Hermes、跑通了第一次对话。接下来要把日常使用固定下来：怎么进界面、怎么用斜杠命令控制它、怎么让本次对话接上上一次的进度。

◆学习目标

  • 分清经典 CLI 与 TUI，知道 `hermes` 和 `hermes --tui` 各自启动什么，以及怎么用 `HERMES_TUI=1` 固定偏好。
  • 记住最常用的启动参数：`-q`、`--model`、`--provider`、`--toolsets`、`-s`、`--verbose`、`-w`、`--yolo`。
  • 会用 `/` 触发斜杠命令，并逐个说清 `/help`、`/model`、`/tools`、`/status`、`/context` 各自的作用。
  • 会在脚本里做非交互调用：`hermes chat -q "…"`、`hermes -z "…"`，以及从文件或 stdin 传入 prompt。
  • 会用 `-c` / `--resume`、`/sessions` 恢复会话，用 `/title`、`hermes sessions list` 管理会话标题与历史。

01这一步在解决什么#

CLI（命令行界面，Command Line Interface）是 Hermes 的原生入口。它是一个完整的终端用户界面，支持多行编辑、斜杠命令（slash command）自动补全、对话历史、中断并重定向，以及流式工具输出——专为常驻终端的用户而生。很多能力（工具开关、会话信息、上下文占用、skill 预加载、会话恢复）在终端里操作最直接。

文档同时维护两套前端：经典 CLI（classic CLI）和更现代的 TUI（Terminal User Interface）。它们共享同一 Python 运行时、相同的 agent、相同的会话、相同的斜杠命令，区别只在交互方式。也就是说，你在这里学会的斜杠命令和会话恢复，换界面不用重学。

CLI 还能被脚本调用：把 prompt 当作参数一次跑完，或从管道和文件读入 prompt。这一步学会之后，后面做自动化、定时任务和批量处理时，Hermes 就只是命令里的一环。

02两种界面：经典 CLI 与 TUI#

Hermes Agent 的 CLI 是一个完整的终端用户界面（TUI），而非 Web UI。它支持多行编辑、斜杠命令自动补全、对话历史、中断并重定向，以及流式工具输出。

文档在经典 CLI 之外还提供了一个现代 TUI：支持模态覆盖层、鼠标选择和非阻塞输入。它和 Classic CLI 共享同一 Python 运行时，相同的 agent、相同的会话、相同的斜杠命令，交互界面更简洁、响应更流畅，文档称它是「以交互方式运行 Hermes 的推荐方式」。

切换只差一个参数：默认 `hermes` 进经典 CLI，加 `--tui` 进 TUI。不想每次敲参数，可以把 `HERMES_TUI=1` 写进环境变量。

bash启动 TUI 与恢复 TUI 会话
# 启动 TUI
hermes --tui

# 恢复最近的 TUI 会话（若无则回退到最近的 classic 会话）
hermes --tui -c
hermes --tui --continue

# 通过 ID 或标题恢复指定会话
hermes --tui -r 20260409_000000_aa11bb
hermes --tui --resume "my t0p session"
bash用环境变量把 TUI 设为默认
export HERMES_TUI=1
hermes          # 现在使用 TUI
hermes chat     # 同上
TUI 的附加要求

TUI 作为从 Python CLI 启动的子进程运行，需要 Node.js ≥ 20，`hermes doctor` 会验证此项。首次启动时 Hermes 会把 TUI 的 Node 依赖安装到 `ui-tui/node_modules`（一次性操作，耗时数秒），后续启动很快。Classic CLI 仍作为默认方式保留。

03启动一个会话：常用参数#

最常用的启动方式就是运行 `hermes`，进入交互式会话。需要一次性指定模型、提供商、工具集或 skill 时，在命令后追加参数即可；这些参数同样适用于 `hermes chat`。

文档「运行 CLI」一节的示例覆盖了日常绝大多数场景：单次查询、指定模型与提供商、指定工具集、启动时预加载 skill。

bash文档中的常用启动方式
# 启动交互式会话（默认）
hermes

# 单次查询模式（非交互式）
hermes chat -q "Hello"

# 使用指定模型
hermes chat --model "anthropic/claude-sonnet-4"

# 使用指定提供商
hermes chat --provider nous        # 使用 Nous Portal
hermes chat --provider openrouter  # 强制使用 OpenRouter

# 使用指定工具集
hermes chat --toolsets "web,terminal,skills"

# 启动时预加载一个或多个 skill
hermes -s hermes-agent-dev,github-auth
hermes chat -s github-pr-workflow -q "open a draft PR"

# 详细模式（调试输出）
hermes chat --verbose
全局选项说明
`--resume <session>`, `-r <session>`通过 ID 或标题恢复之前的会话。
`--continue [name]`, `-c [name]`恢复最近的会话，或恢复最近一个匹配标题的会话。
`--worktree`, `-w`在隔离的 git worktree 中启动，用于并行 agent 工作流。
`--yolo`跳过危险命令的审批提示。
`--tui`启动 TUI 而非经典 CLI。等同于 `HERMES_TUI=1`。
`--profile <name>`, `-p <name>`选择本次调用使用的 Hermes profile（配置文件）。
启动时预加载 skill

如果你已知道本次会话需要哪些 skill，可在启动时用 `-s` 传入（可重复或逗号分隔，如 `hermes chat -s github-pr-workflow -s github-auth`）。Hermes 会在第一轮对话前将每个指定的 skill 加载到会话 prompt 中；该标志在交互模式和单次查询模式下均有效。

04界面上有什么：横幅与状态栏#

进入会话后先看到欢迎横幅，它一目了然地显示当前模型、终端后端、工作目录、可用工具和已安装的 skill。TUI 的横幅还把运行时信息分成四个可折叠区块（Tools、Skills、System Prompt、MCP Servers），Tools 默认展开，其余默认折叠。

输入区域上方是一条持久状态栏，实时更新模型、token 占用、费用和时长。随着上下文变满，进度条颜色会依次变化，提醒你是否该压缩对话。

text状态栏样式
 ☤ claude-sonnet-4-20250514 │ 12.4K/200K │ [██████░░░░] 6% │ $0.06 │ 15m
  • 绿色 < 50%：空间充足
  • 黄色 50–80%：趋于饱满
  • 橙色 80–95%：接近上限
  • 红色 ≥ 95%：即将溢出——考虑使用 `/compress`
元素描述
模型名称当前模型（超过 26 个字符时截断）
Token 计数已使用的上下文 token 数 / 最大上下文窗口
上下文进度条带颜色阈值编码的可视填充指示器
费用预估会话费用（未知或零价格模型显示 `n/a`）
时长会话已用时间
⚠ YOLOYOLO 模式警告——当 `HERMES_YOLO_MODE` 开启时显示（通过启动时的 `hermes --yolo` 或会话中的 `/yolo` 切换）
状态栏会自适应宽度

≥ 76 列时显示完整布局，52–75 列时显示紧凑布局，低于 52 列时显示最简布局（模型 + 时长，以及 YOLO 徽章（如已激活））。想临时隐藏或显示状态栏用 `/statusbar`（别名 `/sb`）。

05键盘操作：发送、换行、中断#

在交互界面里，`Enter` 发送消息，换行需要专门的组合键——因为大多数终端默认对 `Enter` 和 `Shift+Enter` 发送相同的字节序列，应用无法区分。

agent 工作时也可以随时插手：直接输入新消息 + `Enter`，或者在 2 秒内双击 `Ctrl+C` 强制退出。

按键操作
`Enter`发送消息
`Alt+Enter`、`Ctrl+J` 或 `Shift+Enter`换行（多行输入）
`Ctrl+C`中断 agent（2 秒内双击强制退出）
`Tab`接受自动建议（ghost text）或自动补全斜杠命令
`Ctrl+G`在 `$EDITOR`（vim/nvim/nano/VS Code 等）中打开当前输入缓冲区，保存退出后作为下一条 prompt 发送
`F6`打开全屏实时子智能体监视器，保留输入草稿
`Ctrl+D`退出
`Ctrl+Z`将 Hermes 挂起到后台（仅 Unix）。在 shell 中运行 `fg` 恢复
Windows Terminal 用户的换行键

在 Windows Terminal 中，`Alt+Enter` 被终端捕获（切换全屏），永远不会传递给 Hermes——请直接使用 `Ctrl+Enter`（传递为 `Ctrl+J`）或 `Ctrl+J` 来换行。此外，`Shift+Enter` 需要终端通过 Kitty 键盘协议或 xterm 的 `modifyOtherKeys` 模式发送不同序列才能被识别；当终端无法区分时，`Alt+Enter` 和 `Ctrl+J` 在所有终端中均可正常使用。

06斜杠命令：在输入框里敲 /#

输入 `/` 就会弹出自动补全下拉菜单。Hermes 支持大量 CLI 斜杠命令、动态 skill 命令和用户自定义快捷命令。命令不区分大小写（`/HELP` 与 `/help` 效果相同），已安装的 skill 也会自动成为斜杠命令。

下面这几个是最常用的：先用 `/help` 看全量列表，用 `/status` 确认自己在哪个会话、花了多少钱，用 `/context` 看上下文被什么占满了。

text几个常用斜杠命令
/help
/model claude-sonnet-4
/tools
/title My Session Name
/status
/context all
命令作用
`/help`显示命令帮助
`/model`显示或更改当前模型
`/tools`列出当前可用工具（`/tools [list|disable|enable] [name...]` 还能为当前会话禁用/启用特定工具）
`/status`显示会话信息——模型/配置/token/时长——以及本地会话摘要块（近期轮次数、常用工具、涉及文件、最新用户 prompt + 助手回复）。纯本地计算，不调用 LLM
`/context [all]`视觉化上下文占用分解——字形方块网格 + 按类别（system prompt / tools / skills / memory / conversation / 剩余空间）的 token 表；`/context all` 追加逐 skill 与逐工具集的成本。（此条出自官方英文 CLI 页 `docs/user-guide/cli.html`）
`/sessions`在经典 CLI 中直接打开交互式会话选择器（与 TUI 使用同一界面）。输入过滤，方向键导航，Enter 恢复
`/skills browse`浏览 skill 中心和官方可选 skill
`/bg <prompt>`在独立后台会话中运行一个 prompt
`/btw <question>`在不打断当前对话的情况下，就当前对话提出顺带问题
前缀匹配与自定义命令

命令支持前缀匹配：输入 `/h` 解析为 `/help`，`/mod` 解析为 `/model`；当前缀有歧义时，注册表顺序中的第一个匹配项优先，完整命令名和已注册别名始终优先于前缀匹配。你还可以在 `~/.hermes/config.yaml` 里用 `quick_commands` 定义自定义快捷命令（`type: exec` 直接跑 shell 命令、`type: alias` 指向另一个命令），输入 `/status`、`/gpu` 这样使用，无需调用 LLM。

07非交互用法：一次跑完与管道输入#

把 prompt 作为参数传进去，Hermes 就跑一次并退出，这是它在脚本里最常见的形态：`hermes chat -q "Hello"`。需要「只要最终答案」时改用 `hermes -z`——文档称它是脚本化单次调用最纯粹的入口：单个 prompt 输入，最终响应文本输出，stdout 和 stderr 上不输出任何其他内容，无横幅、无 spinner、无工具预览、无 `Session:` 行。

prompt 也可以来自文件和管道。管道场景下有个容易踩的点：通过管道传入 stdin 或在非交互式环境中运行时，Hermes 会回退到单次查询模式，而不是进入交互界面。

bash非交互调用
# 单次查询模式（非交互式）
hermes chat -q "Hello"

# 纯脚本化单次调用
hermes -z "What's the capital of France?"
# → Paris.

# 父脚本可以干净地捕获响应：
answer=$(hermes -z "summarize this" < /path/to/file.txt)

# 程序化模式（抑制横幅/spinner/工具预览）
hermes chat --quiet -q "Return only JSON"
bash从文件或 stdin 读取单次查询（源自官方英文 CLI 页）
# 从文件或 stdin 读取单次查询——内容不经过 shell 解释，
# 任意文本（引号、$(...)、反引号）都会原样传入
hermes chat --query-file prompt.txt
hermes chat --query-file - < prompt.txt
  • `-q`, `--query "..."`：单次非交互式 prompt
  • `-Q`, `--quiet`：程序化模式，抑制横幅/spinner/工具预览
  • `-m`, `--model <model>`：覆盖本次运行的模型
  • `-t`, `--toolsets <csv>`：启用逗号分隔的 toolset 集合
  • `--provider <provider>`：强制指定 provider
  • `-w`, `--worktree`：为本次运行创建隔离的 git worktree
`-z` 与 `-q` 怎么选

文档的建议是：相同的 agent、相同的工具、相同的 skill，`-z` 只是剥离了所有交互式/装饰性层。如果你还需要在记录中包含工具输出，请改用 `hermes chat -q`；`-z` 专门用于「我只需要最终答案」的场景。

08恢复会话：接着上次继续聊#

退出 CLI 会话时，Hermes 会打印恢复命令，形如 `Resume this session with: hermes --resume 20260225_143052_a1b2c3`，并附上会话 ID、时长和消息数。照着敲就能回来。

恢复会从 SQLite 中还原完整的对话历史，agent 能看到所有之前的消息、工具调用和响应——就像从未离开一样。CLI 会话存储在 `~/.hermes/state.db` 中，包含会话元数据（ID、标题、时间戳、token 计数器）、消息历史、跨压缩/恢复会话的谱系。

bash文档列出的恢复选项
hermes --continue                          # 恢复最近的 CLI 会话
hermes -c                                  # 简写形式
hermes -c "my project"                     # 恢复命名会话（谱系中最新的）
hermes --resume 20260225_143052_a1b2c3     # 通过 ID 恢复指定会话
hermes --resume "refactoring auth"         # 通过标题恢复
hermes -r 20260225_143052_a1b2c3           # 简写形式
  • `/title My Session Name`：在聊天中为当前会话命名
  • `/sessions`：在交互式选择器中浏览并恢复历史会话
  • `hermes sessions list`：从命令行浏览历史会话
  • `hermes sessions rename <id> <title>`：从命令行重命名会话
带标题的会话更好找

给会话起个名字之后，`hermes -c "my project"` 和 `hermes --resume "refactoring auth"` 都能直接用标题定位，比记 ID 轻松得多。

常见坑

01`hermes` 和 `hermes --tui` 到底该用哪个？+

两者是同一个 agent、同一套会话、同一套斜杠命令，随时可以换。经典 CLI 是默认方式，TUI 更现代（模态浮层、鼠标选择、非阻塞输入），但需要 Node.js ≥ 20，首次启动还要装一次 Node 依赖。想固定用 TUI，把 `HERMES_TUI=1` 写进环境变量即可。

02在 Windows Terminal 里按 `Alt+Enter` 没换行，反而全屏了。+

`Alt+Enter` 被终端捕获（切换全屏），永远不会传递给 Hermes。请直接使用 `Ctrl+Enter`（传递为 `Ctrl+J`）或 `Ctrl+J` 来换行。`Shift+Enter` 只有在终端通过 Kitty 键盘协议或 xterm 的 `modifyOtherKeys` 模式发送不同序列时才可区分。

03`/model` 里找不到我想用的新提供商。+

`/model` 只能在已配置的提供商之间切换，它无法添加新提供商、运行 OAuth 或提示输入 API 密钥。先退出会话（`Ctrl+C` 或 `/quit`），再从终端运行 `hermes model`——那是完整的 provider 设置向导。

04把内容通过管道喂给 Hermes，结果没进交互界面。+

文档明确：通过管道传入 stdin 或在非交互式环境中运行时，会回退到单次查询模式。脚本里想要纯文本回复用 `hermes -z "…"`（无横幅、无 spinner、无工具预览、无 `Session:` 行）；还想在记录里保留工具输出，就用 `hermes chat -q`。

05按 `Ctrl+Z` 挂起没有反应。+

挂起到后台仅 Unix 支持，Windows 不支持此功能。在 Unix 上按 `Ctrl+Z` 后，shell 会打印「Hermes Agent has been suspended. Run `fg` to bring Hermes Agent back.」，输入 `fg` 即可从中断处恢复会话。
