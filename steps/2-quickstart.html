01这一步在解决什么#

装好 Hermes 只是走完一半路，真正的分界线是你能不能看懂启动后的屏幕，然后完成一次有实际结果的对话。官方把这部分叫做 quickstart（快速入门），因为新手最常掉进的坑就是“安装成功但什么都做不了”。

屏幕上的信息比想象中多：最上方是欢迎横幅（banner），写着当前模型、终端后端、工作目录、可用工具和已安装的 skills；输入区上方是一条实时状态栏，显示 token 用量、上下文进度条、预估费用和会话时长。看懂这几处，你就能自己判断 Hermes 是在正常干活，还是已经卡住或配错了。

本节还立一条纪律：先让一次完整对话跑通，再叠加 gateway、cron、skills、语音或 provider 路由。每一步都有可以观察的成功标志，读完你应该能独立判断这台机器上的 Hermes 是否处于健康状态。

021. 启动：hermes 与 hermes --tui 怎么选#

Hermes 提供两种终端界面，命令都在同一台机器上：经典的 prompt_toolkit CLI，以及更新的 TUI（终端用户界面）。两者共享相同的会话、斜杠命令和配置文件，用一个界面开始的对话，可以在另一个界面里恢复。

直接输入 hermes 进入经典 CLI；输入 hermes --tui 进入现代 TUI，官方把它列为以交互方式运行 Hermes 的推荐方式，因为它有模态浮层面板、鼠标选择和“非阻塞输入”（会话就绪前就能把话打完排队）。TUI 需要 Node.js ≥ 20，首次启动会把 Node 依赖装到 ui-tui/node_modules，只花几秒；hermes doctor 会验证这一项。

bash任选其一启动
hermes            # 经典 CLI
hermes --tui      # 现代 TUI（推荐）
  • 经典 CLI：默认方式，流式工具输出、多行编辑、历史记录、中断并重定向。
  • TUI：即时首帧、富浮层面板、鼠标拖拽选择、备用屏幕渲染（退出后不残留滚动历史）。
  • 两者快捷键、斜杠命令、personality 与 skin 完全一致；界面上的差别只是呈现方式。
TUI 也能用环境变量打开

export HERMES_TUI=1 之后再运行 hermes 或 hermes chat，就会走 TUI。如果 stdin 被管道接管或在非交互环境里运行，程序会回退到单次查询模式，不会有交互界面。

032. 启动横幅：屏幕最上方那几行读什么#

启动后第一眼看到的是一块欢迎横幅，它一目了然地列出当前模型、终端后端、工作目录、可用工具和已安装的 skill。你的第一项自检就是在这里找到自己选的模型名和 provider，如果这里显示的和你以为的不一样，后面所有操作都不必再看。

TUI 的横幅把运行时信息拆成四个可折叠区块：Tools、Skills、System Prompt、MCP Servers。点击区块标题（或标题旁的 ▸ / ▾ 折叠箭头）就能展开或收起。Tools 默认展开，因为它是会话开始时最常看的东西；另外三个默认折叠，所以即使装了很多 skill 或接了几个 MCP server，横幅也不会刷满整屏。

  • Tools — 默认展开：本次会话真正可调用的工具清单。
  • Skills — 默认折叠：已安装的 skill，也就是可复用的工作流包。
  • System Prompt — 默认折叠：实际发给模型的系统提示词，可用来自查人格和规则。
  • MCP Servers — 默认折叠：通过模型上下文协议接入的外部工具服务器。
折叠状态不会保存

区块的展开/折叠状态只对当前这块横幅有效，下次启动会重置为默认值，所以不必担心把界面改乱。

043. 状态栏：一行字符里的模型、上下文和费用#

输入区上方有一条持久状态栏，实时更新。它的样子是这样一串竖线分隔的字段，第一次看确实不像人话，但拆开只有五类信息。

最需要盯的是上下文进度条：它显示已用 token 除以模型最大上下文窗口。条的颜色按阈值变化——绿色表示空间充足，黄色说明趋于饱满，橙色接近上限，变成红色（≥ 95%）就该考虑用 /compress 压缩上下文了。状态栏会按终端宽度自适应：≥ 76 列显示完整布局，52–75 列显示紧凑布局，低于 52 列只留模型和时长。

text状态栏示例（来自官方 CLI 文档）
 ☤ claude-sonnet-4-20250514 │ 12.4K/200K │ [██████░░░░] 6% │ $0.06 │ 15m
  • 绿色（< 50%）：空间充足。
  • 黄色（50–80%）：趋于饱满。
  • 橙色（80–95%）：接近上限。
  • 红色（≥ 95%）：即将溢出，考虑使用 /compress。
元素含义
模型名称当前模型，名字超过 26 个字符会被截断
Token 计数已使用的上下文 token 数 / 最大上下文窗口
上下文进度条带颜色阈值编码的可视填充指示器
费用预估会话费用；未知或零价格模型显示 n/a
🗜️ N上下文被自动压缩的次数，首次压缩后出现
▶ N仍在运行的 /bg 后台任务数，有任务时才显示
时长会话已用时间
⚠ YOLOYOLO（自动批准）模式警告，与横幅警告同步

054. 第一句 prompt 与运行中的画面#

横幅出现、状态栏亮起之后，在 ❯ 提示符后面输入内容，按 Enter 发送。第一句 prompt（提示词）最好“具体且易于验证”——问一个你能立刻检查答案对不对的问题，而不是“你能做什么”。官方给的三个起点都属于这一类。

发送后屏幕会动起来：模型思考期间显示一组表情动画和计时，随后是工具执行信息流，每行以 ┊ 开头，写明工具名和耗时。这两处就是“它真的在干活”的证据，而不是卡住了。默认的静默模式会抑制工具详细日志、保留这套简洁反馈；想看得更多，用 /verbose 在 off → new → all → verbose 之间循环切换。

text可直接照抄的三句 prompt
Summarize this repo in 5 bullets and tell me what the main entrypoint is.

Check my current directory and tell me what looks like the main project file.

Help me set up a clean GitHub PR workflow for this codebase.
text思考动画
  ◜ (｡•́︿•̀｡) pondering... (1.2s)
  ◠ (⊙_⊙) contemplating... (2.4s)
  ✧٩(ˊᗜˋ*)و✧ got it! (3.1s)
text工具执行信息流
  ┊ 💻 terminal `ls -la` (0.3s)
  ┊ 🔍 web_search (1.2s)
  ┊ 📄 web_extract (2.1s)
  • 成功标志一：横幅显示你选择的模型 / provider。
  • 成功标志二：Hermes 无错误地回复。
  • 成功标志三：需要时能够使用工具（终端、文件读取、网页搜索）。
  • 成功标志四：对话可以正常进行超过一轮。
  • 四点全中，最难的配置部分就已经过了。

065. 斜杠命令、多行输入与中断#

在输入框里单独打一个 /，屏幕会弹出所有命令的自动补全下拉列表，用方向键选、Tab 接受。命令不区分大小写，/HELP 与 /help 效果相同；已安装的 skill 也会自动注册成同名斜杠命令，例如安装 gif-search 之后就能直接输入 /gif-search funny cats。

长句子可以换行再发：Alt+Enter、Ctrl+J 或 Shift+Enter 都会插入新行。Shift+Enter 需要终端能把它和 Enter 区分开（Kitty、foot、WezTerm、Ghostty 默认支持；iTerm2、Alacritty、VS Code 终端等要启用 Kitty 键盘协议）。Alt+Enter 和 Ctrl+J 在所有终端里都能用。

如果 agent 响应太久，直接输入新消息再按 Enter 就是最常用的中断方式：当前任务被打断，改做你的新指令，Ctrl+C 同样有效。注意这是默认行为（display.busy_input_mode 为 interrupt），想不打断就补话，可以切成排队或注入模式。

text三种忙碌输入模式，可在会话中随时切换
/busy queue
/busy steer
/busy interrupt
/busy status
命令功能
/help显示所有可用命令
/tools列出可用工具
/model交互式切换模型
/status会话信息：模型 / 配置 / token / 时长，以及本地会话摘要
/sessions打开交互式会话选择器，输入过滤、方向键导航、Enter 恢复
/save保存对话
/personality pirate尝试一个有趣的人格
Windows Terminal 里换行要用对键

在 Windows Terminal 中 Alt+Enter 会被终端自己捕获（切换全屏），永远不会传给 Hermes；此时请用 Ctrl+Enter（传递为 Ctrl+J）或 Ctrl+J 换行。macOS Terminal.app 和 Windows Terminal 稳定版无法区分 Shift+Enter，同样改用 Ctrl+J。

076. 会话保存与恢复#

退出 CLI 时它不会悄悄走掉：屏幕上会打印出这一段的统计（会话 ID、时长、消息条数）以及一条恢复命令，把那行命令存下来，下次就能原样回到这里。

恢复会从 SQLite 状态数据库（~/.hermes/state.db）里还原完整对话历史，agent 能看到所有之前的消息、工具调用和响应，就像从未离开。日常最省事的做法是 hermes --continue 或简写 hermes -c；要精确回到某一次，就用 --resume 加会话 ID 或标题。

text退出时打印的恢复信息
Resume this session with:
  hermes --resume 20260225_143052_a1b2c3

Session:        20260225_143052_a1b2c3
Duration:       12m 34s
Messages:       28 (5 user, 18 tool calls)
bash恢复会话的两种写法
hermes --continue    # 恢复最近的会话
hermes -c            # 简写形式
找不到旧会话时

先运行 hermes sessions list 看看会话是否真的存在，并确认你在正确的 profile 下——换了 profile（配置档）就看不到另一个 profile 的会话。

087. 出问题时：六步恢复工具包#

当“感觉哪里不对”说不清原因时，按下面这个固定顺序敲一遍，就能从不确定状态回到已知的正常状态。它的设计意图是先诊断、再改配置、最后重开会话，避免一边报错一边加新功能。

顺序跑完仍然不通，就以一条最普通的对话作为底线：能聊通一轮，再去碰 gateway、cron、skills 这些附加层。

  • hermes doctor —— 诊断配置和环境问题
  • hermes model —— 重新确认 provider、模型和认证
  • hermes setup —— 重跑完整配置向导
  • hermes sessions list —— 确认会话和 profile
  • hermes --continue —— 回到刚才的上下文
  • hermes gateway status —— 只在你接了消息平台时才需要
上下文不足会被直接拒绝

Hermes 要求模型至少有 64,000 token 的上下文窗口，太小的模型启动时就会被拒绝。托管模型（Claude、GPT、Gemini、Qwen、DeepSeek）都满足；自托管的话要手动调大，例如 llama.cpp 用 --ctx-size 65536，Ollama 用 -c 65536。

常见坑

01Hermes 启动了，但回复为空或者内容明显异常？+

多半是 provider 认证或模型选择有问题。重新运行 hermes model，确认 provider、模型名称和认证信息都对；如果用的是自定义 endpoint，先用一个独立客户端单独验证它能不能正常返回。

02启动时直接被拒绝，提示上下文不够？+

Hermes 要求模型至少具备 64,000 token 的上下文窗口，小窗口模型无法支撑多步骤工具调用，启动阶段就会被拒。换成托管模型即可；本地模型要显式调大，例如 llama.cpp 的 --ctx-size 65536、Ollama 的 -c 65536。

03按 Shift+Enter 不换行，反而触发了别的功能？+

多数终端默认把 Enter 和 Shift+Enter 发成同样的字节，程序无法区分。Windows Terminal 里 Alt+Enter 还被终端自己占用（切换全屏），请改用 Ctrl+J 或 Ctrl+Enter；Alt+Enter 和 Ctrl+J 在所有终端中都可用。

04只想补一句话，结果把 agent 正在做的事打断了？+

这是默认行为：agent 工作时按 Enter，消息会中断当前操作并立即处理。想不打断可以切模式——/busy queue 让你的话排队等这一轮结束，/busy steer 则在下次工具调用后把补充意见送进当前运行。/busy status 可以查看当前模式。

05hermes --continue 找不到之前的会话？+

两个常见原因：切换过 profile，或者那段对话根本没保存成功。先跑 hermes sessions list 看清单，确认自己在同一个 profile 下，再考虑用 --resume 加会话 ID 或标题精确恢复。
