让 Hermes 真的动手干活

Tools

工具是它的手，工具集是工具箱

前五步你已经装好 Hermes、配好模型、能在命令行里对话。这一步解决最后一个疑问：它凭什么能替你读文件、跑命令、改数据？答案是把工具（Tool）交给它，同时你知道怎么翻看、怎么限制、怎么扩。

◆学习目标

  • 能说清工具与工具集的关系，并知道工具集分核心（Core）、复合（Composite）、平台（Platform）三类
  • 会用 /tools list、/toolsets、/tools disable|enable 和 hermes tools 查看与控制当前可用工具
  • 知道 terminal、process、read_file、write_file、patch、search_files 这类工具能做什么，以及危险命令的审批机制
  • 能用一句自然语言让 Hermes 读取本地 CSV、统计汇总并生成结果文件，并验证它真的写出来了
  • 能说明技能（Skills）与 MCP 各自解决什么问题，以及 MCP 配置完成后要用 /reload-mcp 重载

01这一步在解决什么#

聊天模型只会输出文字，真正让 Hermes 从「会说」变成「会做」的是工具（Tool）——读文件、执行命令、搜索网页、写文件这些实实在在的动作。工具被编成工具集（Toolset），一个工具恰好属于一个工具集；启用某个工具集，里面所有工具就对 Agent 可用。这是 Hermes 按平台、按会话、按任务决定「它能做哪些事」的主要机制。

大部分新手出问题的场景不是「模型不聪明」，而是「它根本没拿到那个工具」。所以第 6 步的重点不是背工具列表，而是建立三个动作习惯：先看清当前会话有哪些工具（/tools list、/toolsets），再按需开关（hermes tools、--toolsets），最后知道风险在哪里、谁来批准（危险命令审批、终端后端）。

工具不是一成不变的。内置工具通常有七十个左右，不够用时你有两条正规扩展路径：用技能（Skills）教会它以你的方式做事，或者用 MCP 把外部的工具服务器接进来，变成和内置工具一样的工具。走完这一步，你就从「会聊天」进入了「会指挥」的阶段。

02工具与工具集：一个管「能做什么」，一个管「给谁做」#

工具（Tool）是 Hermes 真正能调用的一个函数——读文件、跑终端命令、搜网页、发消息、分析图片。它决定 Agent「能做什么」。工具并不零散地暴露给模型，而是被编成工具集（Toolset）：每个工具恰好属于一个工具集，启用某个工具集，该集合中的所有工具就对 Agent 可用。

工具集分三类：核心（Core）是一组相关工具的逻辑分组，比如 file 含 read_file、write_file、patch、search_files；复合（Composite）把多个核心工具集打包成常用场景，比如 debugging 就是 file + terminal + web；平台（Platform）是针对某个部署环境的整套配置，比如 hermes-cli 是交互式 CLI 会话的默认配置。

文档里把内置工具按用途做了高层分类，先记住这张表，比背工具名有用得多。

分类示例工具能做什么
Webweb_search、web_extract搜索网页并提取页面内容
终端与文件terminal、process、read_file、patch执行命令并操作文件
浏览器browser_navigate、browser_snapshot、browser_vision支持文本和视觉的交互式浏览器自动化
Agent 编排todo、clarify、execute_code、delegate_task规划、澄清、代码执行及子 Agent 委托
记忆与召回memory、session_search持久化记忆与会话搜索
自动化与投递cronjob、send_message定时任务管理，以及出站消息投递
集成ha_*、MCP server 工具Home Assistant、MCP 及其他集成
工具集开关 ≠ 工具开关

hermes tools 提供的是工具级别的开关，比工具集更细；即使某个工具集已启用，被单独禁用的工具依然会被过滤掉，不会出现在模型面前。

03先看清：这个会话到底有哪些工具#

进会话第一件事就是问它：输入 /tools list 列出当前可用工具，输入 /toolsets 列出可用工具集。想临时调整，用 /tools disable browser、/tools enable homeassistant——注意禁用工具会把它从会话工具集中移除，并触发一次会话重置。

启动时就定死也可以。hermes chat --toolsets "web,terminal" 只带这两个工具集起会话，--toolsets all 则全部打开。要按平台长期生效，运行 hermes tools 打开交互式界面逐个开关，或直接写进 ~/.hermes/config.yaml 的 toolsets 列表。

一个细节值得留意：有些工具没出现不是被禁用了，而是没通过可用性检查——比如网页搜索类工具需要搜索服务凭据，x_search 需要 xAI 凭据，image_generate 需要 FAL_KEY，缺凭据的工具根本不会注册进本次会话。

bash会话内查看与调整（斜杠命令）
/tools list
/toolsets
/tools disable browser
/tools enable homeassistant
bash启动时指定工具集 / 交互式按平台配置
hermes chat --toolsets "web,terminal"
hermes chat --toolsets all
hermes tools
yaml~/.hermes/config.yaml 里的平台默认工具集
toolsets:
  - hermes-cli        # CLI 的默认整套
  # - hermes-telegram  # 想给 Telegram 换一套就写在这里

04终端与代码执行：最能干，也最需要看住#

终端（terminal）工具的定位很直白：在真实环境里执行 shell 命令，文件系统在调用之间持久化；配合 process 工具还能把长任务放到后台跑（list、poll、log、wait、kill、write）。文件类工具走的是另一条更安全的路径——read_file、write_file、patch、search_files 分别替代终端里的 cat、写文件、sed 和 grep，改动更精确，也更容易被审查。

执行环境是可以选的。terminal.backend 支持 local（默认，本机运行）、docker（隔离容器）、ssh（远程服务器，Agent 无法修改自身代码）、singularity、modal、daytona、vercel_sandbox。在可信任务上用 local 就够了；一旦让它跑来源不明的代码，换 docker 或 ssh 后端是成本最低的保险。

风险控制做在工具层里：终端工具内置了危险命令审批系统。执行任何终端命令前，Hermes 都会拿 DANGEROUS_PATTERNS 去比对，命中递归删除（rm -rf）、文件系统格式化（mkfs、dd）、SQL 破坏性操作（DROP TABLE）、远程代码执行（curl | sh）、服务操控（systemctl stop）这类模式时，CLI 会弹出交互提示让你批准、拒绝或永久允许；消息平台则通过 /approve（session 或 always）和 /deny 处理。审批按会话跟踪，某个会话里批准过「递归删除」，后续的 rm -rf 就不再重复询问；选「永久允许」会把该模式写进 config.yaml 的 command_allowlist，跨会话生效。

还要知道两件事：需要 sudo 时系统会提示你输密码并在本次会话内缓存（也可在 ~/.hermes/.env 里设置 SUDO_PASSWORD）；而 execute_code 这个「写 Python 脚本调用 Hermes 工具」的能力依赖 Unix 域套接字，只在 Linux 和 macOS 上可用，在 Windows 上会自动禁用，Agent 退回常规的顺序工具调用。

yaml~/.hermes/config.yaml：换后端与调资源
terminal:
  backend: docker        # 或 local, ssh, singularity, modal, daytona, vercel_sandbox
  docker_image: python:3.11-slim
  cwd: "."
  timeout: 180           # 单条命令超时（秒）
  container_memory: 5120 # 容器内存（MB）
  container_persistent: true
终端后端说明适用场景
local在本机运行（默认）开发、可信任务
docker隔离容器安全性、可复现性
ssh远程服务器沙箱隔离，防止 Agent 修改自身代码
singularityHPC 容器集群计算、无 root 权限
vercel_sandboxVercel Sandbox 云微虚拟机带快照文件系统持久化的云端执行
别用 /yolo 图省事

/yolo（以及命令行 --yolo）会跳过所有危险命令审批提示。它存在，但意味着你把「要不要删这个目录」的判断完全交给了模型。教学机器上用它演示一次可以，别把它变成日常配置。

05它是怎么自己一步步做完的：Agent 循环的直观版#

你只给目标，不给步骤。Hermes 内部反复做三件事：判断这一步该调用哪个工具 → 执行工具并把结果收回来 → 看着结果决定下一步。这个「调用—观察—再决定」的循环会一直转到它能直接给出文字回答为止，所以一次任务里出现五六次工具调用是常态。

一轮里它可以同时发多个互不依赖的工具调用（比如同时读三个文件），结果会按你原来的调用顺序整理好再回到对话中；需要对用户提问的工具（如 clarify）则强制按顺序执行。你能看到进度：CLI 里有 spinner 和工具预览，消息平台上有进度消息。

它什么时候停？两种：模型判断已经完成、直接输出答复；或者达到迭代预算上限——默认 500 次迭代（可用 config 里的 agent.max_turns 调整），到顶后会停下并返回已完成工作的摘要。这也解释了为什么长任务最好拆小，或让它把中间结果写进文件，而不是全挂在一条对话里。

  • 任务：「统计桌面 sales.csv 并按地区汇总」
  • 第 1 步：调用 read_file 读取 CSV，看到列名和前几行数据
  • 第 2 步：调用 terminal（或 read_file + 自己的计算）完成分组统计
  • 第 3 步：调用 write_file 把汇总结果写成 sales-summary.md
  • 第 4 步：不再调用工具，直接输出中文结论——循环结束

06练手任务：一句话让它读 CSV 并汇总#

先造一份够真实的数据文件，复制下面这段到你的终端执行，会在桌面生成 sales.csv（含日期、地区、产品、金额四列）。

然后在 Hermes 会话里只说一句自然语言任务，不要指定用哪个工具——这正是要练的地方：让它自己决定 read_file 还是 terminal。

bash第一步：造数据
cd ~/Desktop && cat > sales.csv <<'EOF'
date,region,product,amount
2026-09-01,华东,机械键盘,399
2026-09-01,华北,显示器,1099
2026-09-02,华东,显示器,1099
2026-09-02,华南,鼠标,129
2026-09-03,华北,机械键盘,399
2026-09-03,华东,鼠标,129
2026-09-04,华南,显示器,1099
EOF
wc -l sales.csv
text第二步：把这句话发给 Hermes
读取我桌面上的 sales.csv，按地区分组统计订单数量和金额总和，按金额从高到低排序，把结果写成一张 Markdown 表格保存到桌面的 sales-summary.md，再用一段中文告诉我哪个地区卖得最好。
  • 你应该看到：连续几次工具调用——先是读取文件的调用，中间出现统计过程的调用，最后出现一次写文件的调用
  • 你应该看到：最终回复里有一段中文结论，指出华东金额最高（399+1099+129 = 1627）
  • 你应该看到：~/Desktop/sales-summary.md 真的存在，内容是一张按金额降序排列的表格
  • 验收方式：再让它「用 read_file 打开 sales-summary.md 给我看看」，核对数字是否和你自己算的一致
算错了怎么办

直接用自然语言纠正，例如「华东的金额少算了一笔 1099，重新算并覆盖原文件」。它会重新读文件、重算、重写——这就是工具闭环的价值：修正只需要一次对话，不需要你手动改文件。

07怎么扩：技能打底，MCP 接外#

内置工具不够用时，第一条路径是技能（Skills）。技能不是新工具，而是教会 Hermes「按你的方式做某件事」的知识文档，放在 ~/.hermes/skills/ 下的 Markdown 文件，装上后每个技能自动成为一个斜杠命令。它采用渐进式加载：session 开始时只加载一份紧凑清单（约 3k tokens），真正用到时才通过 skill_view 读取正文——没用到的技能不消耗 token。

第二条路径是 MCP（Model Context Protocol，模型上下文协议）：把 Hermes 外部的工具服务器接进来，GitHub、数据库、文件系统、内部 API 都能变成它能调用的工具。配置写在 ~/.hermes/config.yaml 的 mcp_servers 下，每个服务器在运行时生成一个 mcp-<server> 工具集，工具名带前缀（例如 mcp_github_create_issue）。

MCP 的关键动作不是「连得多」，而是「连得窄」：用 tools.include 白名单只放你真正需要的工具，用 tools.exclude 屏蔽危险操作，enabled: false 则整个跳过该服务器；改完配置用 /reload-mcp 重新加载。官方建议的首批服务器是 filesystem、git、GitHub 这类范围清晰的；一上来就接权限很大的业务系统，风险远大于收益。

yaml一个范围受控的 MCP 服务器示例
mcp_servers:
  github:
    command: "npx"
    args: ["-y", "@modelcontextprotocol/server-github"]
    env:
      GITHUB_PERSONAL_ACCESS_TOKEN: "***"
    tools:
      include: [list_issues, create_issue, search_code]   # 只要这三个
      prompts: false
      resources: false
维度技能（Skills）MCP
本质教它怎么做事的知识文档给它一套外部工具
放在哪~/.hermes/skills/（Markdown + frontmatter）~/.hermes/config.yaml 的 mcp_servers
怎么启用放入目录即生效，或 /skills install / hermes skills install配好服务器后 /reload-mcp，生成 mcp-<server> 工具集
什么时候用有可复用的流程、检查清单、写法约定工具已存在于别处，或要连内部 API、数据库
不确定从哪个技能开始

在会话里输入 /skills 查看已安装列表，或 /skills browse 浏览官方可选技能；也可以用 hermes skills list 在终端里看。技能写起来也不难，官方文档的 creating-skills 页面把它压缩成了「建目录 + 写 SKILL.md + 测试」三步。

常见坑

01我让它搜网页 / 生图，它说没有这个工具。+

先 /tools list 确认工具在不在。常见三种原因：该工具被单独禁用了（/tools disable 或 hermes tools 里关掉了）；工具集没启用（用 --toolsets 加上 web、image_gen 等）；或者缺凭据——网页搜索需要搜索服务密钥，x_search 需要 xAI 凭据，image_generate 需要 FAL_KEY。没有凭据的工具不会注册，模型根本看不到。

02它执行 rm -rf 之前会问我吗？为什么有时问、有时不问？+

会问。终端工具在执行前比对 DANGEROUS_PATTERNS，命中危险模式时 CLI 会弹审批提示，消息平台用 /approve（session 或 always）与 /deny 处理。审批按会话记忆：同一会话里批准过一次「递归删除」，之后的 rm -rf 就不再提示；如果当时选了「永久允许」，该模式会写进 config.yaml 的 command_allowlist，跨会话生效——感觉「再也不问了」多半是这个原因。

03execute_code 一直提示不可用。+

这是预期行为：代码执行依赖 Unix 域套接字，只在 Linux 和 macOS 上可用，Windows 上会自动禁用，Agent 会回退到常规的顺序工具调用。要在 Windows 上做多步数据处理，就让它用 terminal 跑一段 Python 脚本，或让它把中间结果写成文件再处理。

04任务跑到一半停了，只给我一份摘要。+

多半撞到了迭代预算——默认 500 次迭代（agent.max_turns），到顶后会停止并返回已完成工作的摘要。把任务拆小、让它把中间结果写进文件再继续，或者把反复出现的步骤沉淀成技能，都比硬顶这 500 次更划算。

05它改坏了我的文件，怎么补救？+

用 /rollback 列出并恢复文件系统检查点——Hermes 在破坏性文件变更前会自动为工作目录建快照（配置里可用 --checkpoints 显式开启）。此外，把 terminal.backend 换成 docker 或 ssh 能从根本上把影响限制在沙箱里。
