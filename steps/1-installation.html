安装 Hermes Agent

Installation

用一行命令把 Hermes 装到电脑或手机上

你刚听说 Hermes，想先在自己手上这台机器把它跑起来，看到它回你一句话。或者在多台机器（笔记本、服务器、手机）上部署，需要知道每种系统到底该跑哪条命令、装完东西落在哪里。

01这一步在解决什么#

安装是唯一必须先跨过去的门槛：后面的模型配置、技能（skills）、消息平台网关（gateway）全都建立在这套本地环境之上，环境没装好，后面每一步都是白折腾。Hermes 也不是一个 pip 包——官方只支持由安装脚本在 ~/.hermes/hermes-agent 下创建一个受管理的隔离环境（独立的 uv 托管解释器和虚拟环境 venv），请勿使用 pip install hermes-agent。

自己手工补依赖很容易漏件，而漏件的代价是某个功能静默失效：缺 ffmpeg 语音合成（TTS）就出不来音频，缺 ripgrep 文件搜索就变慢，缺 Node.js 则浏览器自动化直接不可用。安装程序会检测缺失的依赖并自动安装，所以真正要你操心的前置条件只有一个——Git。

这一步的终点非常明确：新开一个终端，敲 hermes 能进聊天并拿到一条回复。文档里的经验法则是，如果 Hermes 连一次正常对话都完成不了，就暂时不要添加 gateway、cron、skills 这些更复杂的东西，先让一条完整对话跑通。

02先选一条安装路径#

Hermes Agent 支持三种落地方式：Linux / macOS / WSL2 用一行 shell 命令、Windows 原生直接在 PowerShell 里装、Android 手机在 Termux 里装。三种方式跑的都是官方安装程序，区别只在于它是去下载 PortableGit 还是复用你系统里已有的工具。

注意：Windows 现在可以不装 WSL 就原生运行 Hermes——CLI、gateway、TUI（终端界面）和工具都能原生跑；原生安装与 WSL2 安装还能干净共存，因为原生数据在 %LOCALAPPDATA%\hermes，WSL 数据在 ~/.hermes。

你的环境怎么装去哪一节
Linux / macOS / WSL2终端里跑一行 curl 安装命令第 2 节
Windows（原生，无需 WSL）PowerShell 里跑 iex (irm …)第 3 节
Android 手机（Termux）在 Termux 里跑同一条 curl 命令，安装程序自动识别第 4 节
Nix / NixOS用官方 Nix flake，而不是 curl 脚本见 Nix & NixOS 安装配置指南
如果你用 Nix

在 NixOS、macOS 或 Linux 上使用 Nix 的读者有专门路径：Nix flake、声明式 NixOS 模块和可选的容器模式。除安装步骤外，之后的 hermes setup、hermes gateway install、编辑配置与标准安装完全相同。

03Linux / macOS / WSL2：一行安装命令#

这是最省事的方式。基于 git 的安装方式会跟踪 main 分支，也就是说以后升级只需一条 hermes update，立刻就能拿到最新变更。

把下面这行粘进终端回车，脚本会自己下载、克隆仓库、装依赖、建虚拟环境，最后把 hermes 命令挂到你的 PATH 上。

bashLinux / macOS / WSL2 / Android (Termux) 通用的一行安装命令
curl -fsSL https://hermes-agent.nousresearch.com/install.sh | bash
  • 安装位置固定在 ~/.hermes/hermes-agent，这是官方唯一受支持的安装方式（包括开发用途）。
  • 不要用 pip install hermes-agent，那样装出来的不是一个受管理的隔离环境。
  • 需要从源码安装、贡献代码或锁定某个分支时，走贡献指南里的开发环境配置章节。

04Windows 原生：在 PowerShell 里安装#

原生 Windows 无需 WSL 即可运行 Hermes。打开 PowerShell（不是 cmd，也不是 git-bash）执行下面这条命令即可开始安装。

安装程序会把仓库克隆到 %LOCALAPPDATA%\hermes\hermes-agent，创建虚拟环境，并把 hermes 加入用户 PATH。因为 PATH 是这次新改的，装完必须重启终端或开一个新的 PowerShell 窗口，hermes 命令才会被找到。

powershell在 PowerShell 中运行，完成 Windows 原生安装
iex (irm https://hermes-agent.nousresearch.com/install.ps1)
  • 安装程序一次处理：uv、Python 3.11、Node.js 22、ripgrep、ffmpeg，以及便携式 Git Bash（PortableGit，约 50MB，来自官方 git-for-windows 发布页，解压到 %LOCALAPPDATA%\hermes\git）。
  • 如果 git 已经在你的 PATH 中，安装程序直接复用现有安装，不会另装一套；这套 Git 不需要管理员权限，也不会干扰任何系统 Git 安装。
  • 它还会把 HERMES_GIT_BASH_PATH 设置为找到的 bash.exe 路径，让 Hermes 在新 shell 中确定性地解析它。
  • 也提供轻量 GUI 安装器（Hermes Desktop）：下载 .exe 运行，首次启动时它在后台调用 install.ps1 配置依赖；桌面应用与 PowerShell 装出来的 CLI 共用同一安装目录和数据目录，可单独或同时使用。
Windows 上只有一个功能受限

CLI（hermes chat、hermes setup、hermes gateway 等）、gateway、cron 调度器、浏览器工具、MCP 服务器都能原生运行；只有 Dashboard 的 /chat 终端面板仅限 WSL2（它需要 POSIX PTY 伪终端，原生 Windows 没有等效实现）。Dashboard 的其余部分（会话、任务、指标）原生可用。

05Android：在 Termux 里安装#

Hermes 提供了 Termux 感知的安装路径，命令和 Linux 那条一模一样。安装程序会自动检测 Termux 并切换到经过测试的 Android 流程，你不需要额外传参数。

这条路径能干净装上 CLI、cron、PTY（伪终端）后台终端、Telegram gateway（尽力而为的后台运行）、MCP、Honcho 记忆和 ACP；浏览器自动化与语音扩展在 Android 上暂不支持。

bash在 Termux 中运行的安装命令（自动识别 Android 环境）
curl -fsSL https://hermes-agent.nousresearch.com/install.sh | bash
  • 自动用 Termux 的 pkg 安装系统依赖：git、python、nodejs、ripgrep、ffmpeg 及构建工具。
  • 用 python -m venv 创建虚拟环境，并自动导出 ANDROID_API_LEVEL 以用于 Android wheel 构建。
  • 优先尝试较宽泛的 .[termux-all] extra，首次编译失败则回退到较小的 .[termux] extra，再失败则回到基础安装。
  • 默认跳过未经测试的浏览器 / WhatsApp 引导，并把 hermes 链接到 $PREFIX/bin，使它在 Termux PATH 中持续可用。
需要完全显式的手动步骤

安装失败要排查时，请照专门的 Termux 指南逐条执行：pkg 安装系统包、git clone 仓库、python -m venv、python -m pip install -e '.[termux]' -c constraints-termux.txt，最后用 hermes --version 与 hermes doctor 验证。

06安装程序替你做了什么，东西装到了哪里#

安装程序自动处理一切——所有依赖（Python、Node.js、ripgrep、ffmpeg）、仓库克隆、虚拟环境、全局 hermes 命令配置以及 LLM 提供商配置。完成后即可开始聊天，你不需要手动装 Python 或 Node.js。

只有 Git 需要你自己确认：确保 git --version 能正常输出即可，其余缺失的依赖安装程序都会检测并自动安装。存放位置取决于你是以普通用户还是 root 身份安装。

  • Root 模式用的是标准 FHS 布局（/usr/local/lib/…、/usr/local/bin/hermes），适合共享机器：一次系统安装可服务所有用户。
  • 每个用户的个人配置（认证、技能、会话）仍然各自存放在自己的 ~/.hermes/ 或显式指定的 HERMES_HOME 下。
  • Hermes 会自动检测安装方式（git 安装程序、Docker 或 NixOS），检测基于安装目录结构，不需要设置任何环境变量；hermes update 会打印对应路径的更新命令，hermes doctor 也会在环境摘要里显示检测结果。
安装方式代码位置hermes 二进制数据目录
用户级（git 安装程序）~/.hermes/hermes-agent/~/.local/bin/hermes（符号链接）~/.hermes/
Root 模式（sudo curl … | sudo bash）/usr/local/lib/hermes-agent//usr/local/bin/hermes/root/.hermes/（或 $HERMES_HOME）
几个后面会用到的词

会话（session）指一次对话的上下文；技能（skills）是 Hermes 可按需加载的操作手册；网关（gateway）指把 Hermes 接到 Telegram、Discord、Slack 等消息平台的后台服务。

07装完之后：重载 shell、配好模型、开始聊天#

先让当前终端认识新命令：重新加载 shell 配置文件，然后直接敲 hermes，你就会进入聊天界面。

如果 hermes 能跑但还没配模型，会提示 API key not set——用 hermes model 交互式选择提供商（provider），或者走最快路径 hermes setup --portal：一个订阅涵盖 300+ 个模型以及 Tool Gateway（网络搜索、图像生成、TTS、云端浏览器），它一次性完成登录、把 Nous 设为提供商并开启 Tool Gateway。

以后只想改某一项设置时不必重跑整个向导，用下面的专用命令即可。

bash重载 shell 配置，然后启动 Hermes 开始聊天
source ~/.bashrc   # 或：source ~/.zshrc
hermes             # 开始聊天！
bash单项重新配置：模型、工具、消息平台、单个配置项
hermes model          # 选择 LLM 提供商和模型
hermes tools          # 配置启用的工具
hermes gateway setup  # 配置消息平台
hermes config set     # 设置单个配置项
hermes setup          # 或运行完整的设置向导一次性配置所有内容
bash最快路径：Nous Portal 一次搞定登录、提供商和 Tool Gateway
hermes setup --portal
  • 验证版本：运行 hermes --version，确认命令确实来自新装的隔离环境。
  • 体检环境：运行 hermes doctor，它会告诉你确切缺少什么以及如何修复。
  • Windows 用户请在新开的终端窗口里验证，否则 PATH 还没刷新，可能仍然提示找不到 hermes。

08非 sudo / 系统服务用户怎么装#

Hermes 支持以专用非特权用户身份运行，例如 hermes systemd 服务账户，或任何没有 sudo 权限的用户。整个安装路径里真正需要 root 的只有 Playwright 的 --with-deps 步骤，它通过 apt 安装 Chromium 所需的共享库（libnss3、libxkbcommon 等）。

安装程序会检测 sudo 是否可用，并在不可用时优雅降级：把 Chromium 二进制装到服务用户自己的 Playwright 缓存里，并打印管理员需要单独运行的确切命令。推荐的分步方式（以 Debian/Ubuntu 为例）如下。

bash第一步：管理员用户一次性安装 Chromium 所需的系统库
sudo npx playwright install-deps chromium
bash第二步：以非特权服务用户身份运行常规安装程序
curl -fsSL https://hermes-agent.nousresearch.com/install.sh | bash
bash完全跳过 Playwright 步骤（无头环境、不需要浏览器自动化时）
curl -fsSL https://hermes-agent.nousresearch.com/install.sh | bash -s -- --skip-browser
bash第三步：让 hermes 对服务用户的 shell 可用（二选一）
# 方案 A — 添加到服务用户的 profile
echo 'export PATH="$HOME/.local/bin:$PATH"' >> ~/.bashrc

# 方案 B — 系统级符号链接（以管理员身份运行）
sudo ln -s /home/hermes/.hermes/hermes-agent/venv/bin/hermes /usr/local/bin/hermes
  • 验证：hermes doctor 现在应能正常运行。
  • 如果报 ModuleNotFoundError: No module named 'dotenv'，说明你在用系统 Python 调用仓库源码中的 hermes 文件（~/.hermes/hermes-agent/hermes），而不是 venv 启动器（~/.hermes/hermes-agent/venv/bin/hermes）——回去修正第三步。
  • 同样的方式适用于 Arch（安装程序使用 pacman，具有相同的 sudo 检测逻辑）、Fedora/RHEL 和 openSUSE；这几个发行版完全不支持 --with-deps，管理员始终需要单独安装系统库，安装程序会打印相应的 dnf/zypper 命令。

常见坑

01敲 hermes 提示 hermes: command not found+

启动器被写到了 ~/.local/bin（Windows 是用户 PATH），当前 shell 还没刷新。重新加载 shell（source ~/.bashrc，或 source ~/.zshrc）；Windows 上请重启终端或开新的 PowerShell 窗口。系统服务账户的 PATH 通常很精简，需要把 $HOME/.local/bin 显式加进去。

02能启动但提示 API key not set+

这是缺少模型提供商配置，不是安装失败。运行 hermes model 交互式配置提供商，或直接 hermes config set OPENROUTER_API_KEY your_key；想省掉逐个管理密钥的麻烦就用 hermes setup --portal。

03运行仓库源码里的 hermes 报 ModuleNotFoundError: No module named 'dotenv'+

你在用系统 Python 调用 ~/.hermes/hermes-agent/hermes 这个源码文件，而不是虚拟环境里的启动器。改用 ~/.hermes/hermes-agent/venv/bin/hermes，并确保它已链接到 PATH 中。

04没有 sudo 时浏览器工具装不上（Playwright / Chromium 依赖）+

让有 sudo 的管理员一次性运行 sudo npx playwright install-deps chromium 装系统库，再以普通用户重跑安装程序（它会检测到缺少 sudo、跳过 --with-deps）；如果这台机器根本不需要浏览器自动化，直接在安装命令后加 --skip-browser。

05Windows 上终端工具或浏览器功能不可用+

32 位 Windows 上 PortableGit 只提供 64 位和 ARM64 资产，安装程序会回退到缺少 bash 的 MinGit，依赖 bash 的功能（终端工具、agent 浏览器）因此被禁用。另外若遇到编码相关的 bug，可设置 HERMES_DISABLE_WINDOWS_UTF8=1 回退到旧版 cp1252 stdio 路径用于问题定位。
