IMA Knowledge Base

核心功能：对接 IMA 知识库

把 ima 里的私有文档和截图挂进对话，让回答基于你自己的素材，而不是泛泛的互联网印象。

01开始之前，先确认三件事

  • WorkBuddy 正常运行：客户端能启动、能正常发起一轮对话。
  • 安装 ima 客户端并创建知识库：在 ima 里新建知识库，把要用的文档、截图放进去。
  • 配置打通两者服务：让 WorkBuddy 与 ima 建立连接，保证知识库能被读到。

检查怎么确认已经就绪

  • ima 里能看到知识库条目，且条数不为 0。
  • WorkBuddy 的「知识库」面板里能选到刚才那个 ima 知识库。
两项都成立，再进入「操作步骤」；否则先解决连接问题，后面导入会白做一遍。

02三步把知识库接进来

  1. 1打开文档在 WorkBuddy 里打开要处理的文档，或直接进入对话窗口。
  2. 2导入 ima 知识库从知识库面板选择 ima 里建好的那个库，导入到当前会话。
  3. 3Workbuddy 调用 ima 素材作为对话上下文导入后正常提问即可，回答会引用库里的内容。

提示这一步最容易出问题的地方

  • 先导入、再提问：顺序反了，这一轮回答不会带上知识库内容。
  • 素材越具体，回答越准：把关键文档和截图一起放进库，比只放一篇效果好。
  • 提问时写明出处范围（「只根据 my-kb 回答」），能明显减少跑题。

03接通之后能得到什么

让 AI 基于你的私有文档、截图素材精准问答——回答的依据来自你自己放进知识库的东西。

私有文档里的具体条款 截图里的表格与数据 内部术语、代号、项目名 同一份材料的多轮追问

对比接与不接的区别

  • 不接知识库：只能回答公开常识，问到你自己的材料就开始含糊。
  • 接上知识库：答案落在你的素材里，还能给出引用的文件出处。
知识库只在你本机的 ima 里维护，WorkBuddy 是按需调用，不需要把文件搬到别处。
Get Started

两种用法，按你的习惯挑一个

普通用户走图形版，鼠标点几下就能用；开发者走命令行版，方便接进脚本和现有的工作流。

GUI 图形桌面版

面向普通用户

可视化窗口，全部操作靠鼠标完成：启动、选模型、挂知识库、开始对话。

  1. 1下载并安装选择对应系统的安装包，一路默认即可。
  2. 2启动 WorkBuddy打开桌面客户端，首次运行按向导完成基础设置。
  3. 3选择模型在模型下拉框里挑一个（Mimo / Qwen / DeepSeek / GLM / Claude）。
  4. 4挂载知识库打开「知识库」面板，导入 ima 里建好的库。
  5. 5开始对话直接在输入框提问，回答会引用你的私有素材。
全程不需要碰配置文件；换模型、换知识库都在界面上完成。

CLI 命令行版

面向开发者

和图形版共享同一份配置与知识库，适合写进脚本、批处理或 CI 流程。

bash · 常用命令 
# 启动交互式会话（默认模型）
workbuddy chat

# 指定模型发起对话
workbuddy chat --model deepseek-chat

# 挂载 ima 知识库，让回答基于私有素材
workbuddy kb attach ima --name my-kb

# 单次提问，结果可直接重定向到文件
workbuddy ask "总结这份复盘文档的结论" --kb my-kb

# 查看 / 切换当前模型（对应 CC_switch 组件）
workbuddy model list
workbuddy model use qwen-max
Developer Docs

CLI 命令与参数

点标题展开详情。下面每个命令都列出可用参数和一段调用示例，方便直接对照写脚本。

打开一个持续的多轮对话窗口，直到手动退出。图形版和命令行版共享同一个会话历史与配置。

参数说明
--model <name>指定本轮使用的模型，如 deepseek-chat / qwen-max / glm-4 / claude-sonnet / mimo。
--kb <name>挂载一个已配置的知识库作为对话上下文（如 ima 里的 my-kb）。
--config <path>使用指定的配置文件启动，便于隔离不同项目的密钥与默认模型。
# 用 qwen-max 并挂上 my-kb 开始多轮对话 workbuddy chat --model qwen-max --kb my-kb

问一句、拿结果、进程退出，不进入交互模式；适合放进 shell 脚本或定时任务。

参数说明
<prompt>要提问的文本，作为位置参数传入（建议加引号）。
--kb <name>限定回答依据的知识库，回答只引用该库的内容。
-o, --output <file>把结果写入文件，而不是打印到标准输出。
--json以 JSON 输出，便于程序解析（含回答文本与引用来源）。
# 只要 my-kb 里的内容，结果存成文件 workbuddy ask "列出文档里的三条结论" --kb my-kb -o result.md

把外部知识库接到 WorkBuddy 上。对接 ima 时，先确认 ima 客户端里已有建好的知识库。

参数说明
<provider>知识库来源，目前对接 ima 客户端。
--name <name>为挂载的知识库取一个本地名称，供 --kb 引用。
--list列出已挂载的知识库及其来源。
--detach <name>解除某个知识库的挂载。
# 挂载 ima 知识库并命名为 my-kb，之后用 --kb my-kb 引用 workbuddy kb attach ima --name my-kb workbuddy kb attach --list

对应内置的 CC_switch 组件：列出可选模型，或把当前默认模型换成另一个。

参数说明
list列出全部可用模型及其供应方。
use <name>把默认模型切换为指定模型，后续会话沿用。
--current只打印当前默认模型，便于脚本读取。
workbuddy model list workbuddy model use claude-sonnet

管理内置组件：MagPie（素材整理）与 OpenCodeX（代码模块）开关，以及组件状态查看。

参数说明
list列出内置组件及当前启用状态。
enable <name>启用组件，如 magpie、opencodex、cc-switch。
disable <name>关闭组件，关闭后不再出现在会话的工具列表里。
workbuddy ext list workbuddy ext enable opencodex
